# colour: the judges' notes

In each judge's text, A and B are the images as that judge saw them; the line before says which was yours.

## Our screens against the current ones (the goal): your direction 2, the current screens 2, same 0

- **Judge 1** (A was your direction) picked the current screens. The two are nearly identical in layout, type and content. They differ only in how state colour is applied. B fills the running agent cards with a warm tint and border, which separates them clearly from the dashed queued cards. It also gives the Blocked and Running group headers in Compact a red or orange wash, and the live run strip on the ticket page a clearer peach tint, so you can tell group state at a glance. A keeps those surfaces neutral grey, so "running", "queued" and "blocked" rely only on small glyphs and dashed borders, and the hierarchy reads flatter.
  - your direction's gap: Give A's state surfaces a semantic tint. Use a warm fill and border on running agent cards, and a red or orange wash on the Blocked and Running group headers. Then state reads from the surface, not only from 12px glyphs.
  - the current screens's flaw: On My queue, the six peach-filled running cards now carry more visual weight than the three "Your move" rows, the only section that needs the user. Tone the card fills down to a border-only or faint tint, and give the Your move section a stronger surface so it stays the most prominent thing on the page.
  - Broken: Nothing clearly broken in either. Both clip the plan list at the bottom edge on the ticket screens (5, 6, 8), which reads as normal scrolling. In both, the owner dropdown on screen 8 covers the stage track and run strip, which is the expected popover behaviour.
- **Judge 2** (A was your direction) picked the current screens. The two are nearly identical in layout, type, spacing and content on all ten screens. The only real difference is how state colour is used on surfaces. B tints the running agent cards and the run strip on the ticket a warm peach (brown on dark), and gives each group header a stronger tint for its state (red for blocked, orange for running, green for done, pink for the failed query). Running work stands apart from queued work at a glance, and Compact's groups scan faster. A leaves running and queued cards on the same neutral surface, told apart only by a solid or dashed border, so the busiest screen (My queue) reads flatter. Screens 7, 9 and 10 are effectively identical.
  - your direction's gap: Give running agent cards and active-run strips their own state-tinted surface, not the same neutral white or grey as queued cards. Tint the group headers (Blocked, Running, Done, failed query) by state too, so running and queued work, and each group, can be told apart at a glance and not only by a solid or dashed border.
  - the current screens's flaw: On My queue, the peach "Agents at work" band and its six tinted cards are now louder than the "Your move" group, which is the only section that needs the user to act. Make "Your move" the strongest surface on the page (a stronger accent band or heavier header) and pull the running tint back so passive agent activity sits behind it.
  - Broken: Nothing clipped, overlapping or unreadable in either. On screen 8 (A and B) the owner dropdown covers the stage track and run strip, which is expected for an open popover. One small inconsistency in B: the Files icon in the sidebar is grey on screen 10 but gold on the other screens. A keeps it gold throughout.

  - your direction's flaw: Replace the left-to-right gradient fades with a flat, full-width tint: on the Intake "Platform backlog didn't answer" error band (it fades to plain grey on the right, so the error reads as an ordinary group header) and on the ticket's live-run strip.

## The twins against Linear (secondary): your direction 0, Linear 4, same 0

- **Judge 1** (A was your direction) picked Linear. B uses neutral, near-black surfaces with quiet hairline borders and a clear set of text tones. A pushes a navy/indigo tint into every surface and outline, which looks muddy and cheap next to B. A's type scale is also overblown: the "Triage" and "Engineering" titles are huge and heavy, and its chips and buttons are thick blocks, while B keeps titles and controls in proportion. A uses the same ≡ hamburger glyph for filter, display, grouping and a view toggle, so you can't tell them apart. Its popovers also run as one undivided block with uneven gaps (screens 4 and 6). B separates popover sections with dividers, shows dropdowns as real select fields and gives each control its own glyph.
  - your direction's gap: Drop the blue/indigo tint from A's surfaces, borders and selected states and use a neutral grey ramp. Then give every control its own glyph instead of reusing the ≡ icon, add hairline dividers between popover sections, and show the Grouping, Ordering and Completed values as bordered select fields.
  - Linear's flaw: B's secondary text is too faint. In the screen 1 activity feed, actor names, verbs and objects are all the same mid-grey with no weight change, and the timestamps and update bullets (screen 5) fade into the background. Raise secondary text contrast by one step and set actor and object names in the primary colour so each line can be scanned.
  - Broken: B, screen 1: the agent chat panel overlaps the main column, so the right edges of the comment and "connected by" cards run under it and get clipped. B, screen 2: the "Recent" tab and the "Currency" label pills are cut off at the right edge (A also clips its pills there). A, screen 2: the "In Review" group and its rows use a green done-checkmark, which reads as completed rather than in review. A, screen 6: the popover has a large dead gap between "Order completed by recency" and "Show sub-issues" with no divider, so the spacing looks accidental.
- **Judge 2** (A was your direction) picked Linear. B uses neutral charcoal surfaces, lighter type weights and a quiet secondary-text tier, so titles, metadata and chrome sit on clearly separate levels. A tints everything navy, sets nearly all text at the same bright medium weight, and makes the page titles ("Engineering", "Triage", "Mexico launch") oversized and heavy. A also uses the same hamburger "≡" glyph for filter, display, grouping, views and list (Triage shows two identical ≡ buttons side by side), while B gives each control its own glyph (funnel, sliders, sort arrows). B's popovers have hairline dividers between sections and bordered select fields; A's are loose label/value rows floating in empty space with no structure.

Also move the surfaces from navy-tinted to neutral greys and drop secondary text (IDs, timestamps, "Workspace"/"Properties" labels) to a lighter, dimmer weight so the hierarchy reads.
  - Linear's flaw: On the issue screen (screen 1), stop the main column's activity cards from running under the agent panel: give the main column a max width or right padding that clears the panel, so card edges and long comment lines aren't hidden behind it.
  - Broken: B, screen 1: the comment card and the "Linear connected / Changed 2 files" card in the main column run under the right-hand agent panel, so their right edges and borders are hidden (overlap). B, screen 2: the "Recent" tab is cut off at the right edge, and the "Currency" label chips are clipped with no ellipsis. A, screen 2: the label chips are cut off mid-word ("Currency S") with no ellipsis. A, screen 3: the two header buttons use the same ≡ glyph, so filter and display can't be told apart. A, screen 1: the "Changed 2 files" activity row uses a drag-handle (⠿) glyph as its icon.
